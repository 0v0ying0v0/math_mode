# 有效性评分与正负反馈判定规则

> 对应 `spec/iteration_ledger.md` §4/§7/§8 与 `PLAN.md` §6。本文件是**判定算法**，账本只负责填数。

---

## 一、有效性分 E（0–3）

### 三源独立打分

| 源 | 执行者 | 权重倍数 | 打分 |
|---|---|---|---|
| S1 自测 | 求解脚本内断言 | ×1 | 通过=1 / 部分=0.5 / 失败=0 |
| S2 独立复算 | `verify.py`（**禁止 import 求解器**） | ×2 | 同上 |
| S3 红队 | 对立人格子代理 + R1 边界打击 | ×2 | 同上 |

```
E = min(S1, S2, S3) × 3        # 归一到 0–3
```

**为什么取 min 而非加权平均**：加权平均会让"自测满分 + 红队崩盘"伪装成 2.0 分通过。取 min 强制最薄弱环节暴露，且施加"一致性压力"——三个独立视角必须同时认可。

**权重为何是 ×1/×2/×2**：求解器对自己最宽松，故权重最低；独立复算和红队是对抗性的，故加权。加权只影响"部分有效"的排序，不影响 min 的裁决。

### 判定阈值

| E | 含义 | 允许动作 |
|---|---|---|
| 3.0 | 三源一致通过 | 可进入⑤全局验证 |
| 1.5–2.9 | 存在卡线/部分有效 | 仅可保留为**备选**，不得作为主方案 |
| 0–1.4 | 至少一源失败 | **强制回退③**，本轮不得进入⑤ |

> **卡线（borderline）单列**：若测试结果落在判据的 1% 邻域内（如 SOC=20.0%、悬停=300.0 m、截止时刻精确命中），即使 S1 报"通过"，也必须**降级为"部分有效"**并触发 R2 脆弱性打击。原因：卡线解在 ±5% 扰动下必然失效，属于伪可行。

## 二、质量总分 Q（用于算 ΔQ）

```
Q = Σ_问题 ( E_i × w_严重度 ) / Σ_问题 w_严重度 − λ·C_复杂度
```

| 项 | 定义 |
|---|---|
| `w_严重度` | 阻断=4, 高=3, 中=2, 低=1 |
| `C_复杂度` | 归一化复杂度 = 参数净增/基线参数 + 假设净增/基线假设 + LOC净增/基线LOC |
| `λ` | 复杂度惩罚系数，**当前 λ=0.08**（2026-09-25 由 0.15 下调，授权与审计见 `iteration_ledger.md` IT-02 §λ-AUDIT） |

> `λ` 的作用：让"加机制换微小指标提升"的改动自动得负分，从数学上落实奥卡姆剃刀。
> **λ 的取值本身也要被审计**——若有人为了保住自己的方案而调低 λ，属于作弊，须在账本 RB/`λ-AUDIT` 中记录。
> `tests/governance_check.sh` 的 **G-04** 会硬校验 rubric 与账本中的 λ 是否一致，不一致即构建失败。

### λ 调整的固有不对称（必须知情）
λ **调小**会使复杂度惩罚下降、**正向迭代更容易判定成立**；λ **调大**则相反。
因此无论调大调小，都必须走一次 `λ-AUDIT`（授权人、理由、对判定倾向的影响、回滚条件），
否则 `C8 奥卡姆审计` 不成立。**这条不对称是 λ 唯一的滥用面，故用硬检查封死。**

## 三、反馈判定（Decision Rule）

```
输入：Q_this, Q_prev, E_this, 剃刀判决 razor

若 E_this < 1.5                     → ❌ 负反馈，动作=回退③
否则若 razor == "回退"               → ❌ 负反馈，动作=回退（复杂度无收益）
否则若 Q_this > Q_prev + ε          → ✅ 正反馈，动作=保留
否则若 |Q_this − Q_prev| ≤ ε        → ⚪ 中性，动作=合并（并入相邻轮次，不单独计分）
否则                                → ❌ 负反馈，动作=回退+重提问题
```
- `ε` = 0.01，防浮点噪声
- **中性也计入复杂度审计**：中性轮次若增加了假设，等价于负反馈

### 回退的粒度（关键）
**回退 ≠ 全丢**。每个回退事件必须回答：
1. 撤销的**具体内容**是什么（函数/参数/假设/口径）？
2. 该轮中**哪些子结论仍然有效**，予以保留？（写入 RB 的"保留内容"列）
3. 认定失效的**判据编号**是什么（E 值？哪个源？哪个 R 测试？）

## 四、正/负反馈累计看板与健康阈值

| 指标 | 健康区间 | 异常时的强制动作 |
|---|---|---|
| 正/负比 | ≥ 2.0 | < 1.0 → **强制大迭代**：回灌①重审 D 裁决（不是继续在③打补丁） |
| 负反馈的来源集中度 | 分散 | 若 >60% 负反馈集中在**同一类**（如全来自红队 R2）→ 说明该环节建模系统性偏乐观，回灌① |
| E<3 的候选占比 | <20% | 超阈值 → 停止新增功能，先补测试 |
| 假设总数趋势 | 单调不增 | 上升 → 触发剃刀复审 |
| 未决问题数 | =0 | ≠0 且已达迭代上限 → 进入终止保护（诚实清单） |

> **正反馈的定义必须防止"自我强化"**：只有**判决更严或不变**且 Q 上升才算正反馈。
> 若某轮通过"放松判据/放宽约束"来提高 Q，S2/S3 会判定该轮失效（min 规则），自动转为负反馈。
> 这条是整套机制防"自欺"的核心闸门。

## 五、G-A 异常值门（ANOMALY GATE）

**动机**：RB-01 中，"水平能耗占比 1.3–1.9%"这一明显偏小的数值被当作结论写入证据表，
而其真实原因是单位量纲错误（kWh/s 当作 kW，差 3600 倍）。

**判据**
```
对任一观测值 v 与量级预期 E：
  若 v/E > 3  或  E/v > 3   ->  标记 ANOMALY
```

**ANOMALY 处置流程（强制）**
1. **两条独立路径互验**：同一物理量用两种独立算法计算，结果须一致
2. **量纲核对**：写出每一步的单位，确认量纲自洽
3. 通过 → 可写入证据表，并在账本中记录"已过 G-A"
4. 不通过 → 判定为实现缺陷，回灌③

**已应用记录**
| 观测 | 量级预期 | 比值 | 判定 | 结果 |
|---|---|---|---|---|
| 水平能耗占比 1.3–1.9% | 应与水平/爬升能量比同量级（O(1)） | >3 倍偏离 | ANOMALY | 查实为量纲错误（RB-01） |

## 六、G-B 代价核算门（COST-ACCOUNTING GATE）

**动机**：RB-02 中，试图把 Q3 中继架次从 14 降到接近下界 2，未先核算代价即实现，
实测架次数未降、能耗反升 2.5%。

**判据**
```
对任一优化提案 P：
  1. 量化收益 dGain（同一物理口径，数量级）
  2. 量化代价 dCost（实现 P 必然引入的额外消耗，数量级）
  3. 判决：
       dCost < dGain  -> 允许进入实现
       dCost >= dGain -> 否决，记为"负结果"，写入论文并在账本登记
```

**强制要求**
- 核算必须用 `core.py` 的同一物理口径，**不得定性描述**（"可能略增"不合格，须给数量级）
- 核算完成后才允许写第一行实现代码
- 否决的提案须在论文中给出**定量**的不可行理由

**已应用记录**
| 优化提案 | 收益 | 代价 | 判决 | 结果 |
|---|---|---|---|---|
| 合并 Q3 相邻架次中继驻留 | 省 1 架次 ≈ **0.02 kWh** 转移能耗 | 穿越间隔持续悬停 2100–2900 s ≈ **0.63–0.87 kWh** | **代价 ≥ 收益 → 否决** | 记为负结果（IT-13 / RB-02），未再实现 |
