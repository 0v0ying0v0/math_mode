## D1 ｜ 水平巡航功率公式（题面未给）  → P-01

| 项 | 内容 |
|---|---|
| 候选 | (a) 由标准航程反推 `P_g^hor(q) = E_g^use · v_g^c / L_g(q)`；(b) 由爬升效率外推 `P = m g / η_g^↑ · (v_g^c / v_g^↑)` |
| **选择** | **(a)** |
| 理由 | 附录2 只定义"标准航程"而未定义巡航功率；将标准航程解释为"该载荷下耗尽单组可用能量的水平巡航航程"是使 `E_g^use` 与 `L_g` 唯一相容的读法。(b) 无题面依据（爬升效率是竖直方向效率，不能外推到水平） |
| 影响面 | 全题能耗；但**实测水平项仅占架次能耗 1.3–1.9%**（E8），爬升项主导 |
| 验证 | V4.2 口径对抗（(a)/(b) 各跑一遍，比较指标差异） |
| 状态 | **已裁决** |

**推论（必须写进论文）**：`P_g^hor(q)` 随 `q` 单调增（因 `L_g(q)` 单调减），与附录2 Eq.1 的 3/2 指数一致。

## D2 ｜ 下降段水平能耗是否计入  → P-01

| 项 | 内容 |
|---|---|
| 候选 | (a) 计入水平巡航能耗；(b) 下降段不再单独计任何能耗 |
| **选择** | **(a) 计入水平项，不计下降附加项** |

| 影响面 | 低（水平项占比 <2%） |
| 验证 | V2.3 量纲一致性 + V3.1 平地退化 |
| 状态 | **已裁决** |

## D3 ｜ 爬升/下降的水平位移如何计入  → P-01

| 项 | 内容 |
|---|---|
| 候选 | (a) 水平位移并入 `d_{ij}` 一次（"平面投影 + 纯竖直爬升"）；(b) 忽略爬升/下降的水平位移（巡航距离 = `d_{ij}`）；(c) 按倾角分解为斜距 |
| **选择** | **(b) 巡航距离 = `d_{ij}`，水平能耗按 `d_{ij}` 一次计** |
| 理由 | 附录2 原文"任意两个任务节点之间采用**两节点水平直线**作为运输航段"，且分别给出 `d_{ij}`（水平）、`h_{ij}^↑`、`h_{ij}^↓` 三个**独立**量；航段按"爬升→巡航→下降"三段串行，故水平距离归属巡航段。(a) 与 (c) 都会把 `h` 混进水平量，与题面把 `d` 与 `h` 分开给定不一致 |
| 影响面 | 低：爬升高度 ≪ 水平距离（如 S001 爬升 145 m vs 水平 3067 m，比值 4.7%），(a)/(b) 差异 <0.1% |
| 验证 | V4.2 口径对抗（增设 (a) 变体比较） |
| 状态 | **已裁决** |

## D9 ｜ 首批截止时间与期望送达时间的约束强度  → 待测 ★影响可行域

| 项 | 内容 |
|---|---|
| 候选 | (a) 首批 = **硬约束**；期望送达时间 = **软目标**（加权迟延）；(b) 两者都是硬约束；(c) 两者都是软目标 |
| **选择** | **(a)** |
| 理由 | 题面原文：Q2"**医疗物资应满足**附件给出的期望送达时间要求，**首批保障货箱应满足**首批截止时间要求，**其他物资的期望送达时间用于衡量配送及时性**"。三个分句强度不同：前两句用"应满足"，第三句明说"用于**衡量**"。故：首批截止 = 硬；医疗期望 = 硬（"应满足"）；其他期望 = 软（衡量及时性） |

| 影响面 | **高**：决定 Q2/Q3 可行域大小 |
| 验证 | V2.2 + 可行性扫描；若硬约束导致不可行，则立 `D9b` 并记录 |

## D14 ｜ Q4 中 K 个任务组的执行方式：并行 vs 串行  → 用户裁决

| 项 | 内容 |
|---|---|
| 候选 | (a) K 个任务组**并行**执行（各自从 t=0 起算）；(b) 任务组**串行**执行（前组完成后下组才开始） |
| **选择** | **(a) 并行** —— 用户明确指示"**并行优先**" |
| 理由 | 题面原文："考虑到灾后救援中可能需要将整体任务划分为若干**相对独立的执行单元**"。"独立执行单元"的语义支持并行；若为串行，"独立"一词无实际意义（仍是一台机器顺序干活） |
| **量化影响（关键）** | 由 `code/q4_partition.py` 实测，并已按 G-B 门核算：<br>· **资源需求两种口径下完全相同** —— 因 T-4.6 规定"任务执行期间各类资源**不得跨组调配**"，故无论并行还是串行，每组都须独立配置，总需求 = 各组之和<br>· 差异仅在**时间轴**：K=2 并行 22219.4 s vs 串行 43660.2 s（**并行快 2.0 倍**）；K=3 并行 14057.7 s vs 串行 41498.8 s（**并行快 3.0 倍**） |
| 影响面 | **低**：资源需求量与缺口不受影响，仅"完成时间"指标变化 |
| 验证 | `out/Q4_方案比较.csv`（并行口径）；本文件量化对比段落 |
| 状态 | **已裁决（用户指示）** |

> **结论**：D14 的裁决**不影响资源核算结论**（第 (2) 问的核心），只影响完成时间（第 (1) 问）。
